# EcomDispute M2 真实 LLM 对照评测

## 实验设置

- 日期：2026-08-22
- 模型：`gpt-5.4-mini-2026-03-17`
- 数据：20 个固定退款案例，10 个独立人工编写、10 个规则生成
- 输入隔离：Oracle 仅由评测器读取，未进入 Prompt、业务数据库、Skill 或工具返回
- 工具预算：两种模式使用相同的订单、支付、退款、售后和版本化政策工具
- 首轮原则：保留全部首轮结果，不选择性重跑失败案例

对照模式：

1. Hybrid：一次真实 LLM 对话语义提取，事实查询、政策选择和 Evidence Fusion 由确定性模块执行。
2. Tool Calling Baseline：单个真实 LLM Agent 自主并行调用工具并直接输出结构化裁决。

## 总体结果

| 指标 | Hybrid | Tool Calling Baseline |
|---|---:|---:|
| 案例数 | 20 | 20 |
| 全项通过 | 19/20 | 11/20 |
| 最终裁决正确 | 20/20 | 14/20 |
| 责任方正确 | 20/20 | 14/20 |
| 复检分流正确 | 20/20 | 13/20 |
| LLM 语义路由正确 | 19/20 | 不单独拆分 |
| 引用 Evidence ID 均真实 | 20/20 | 20/20 |
| LLM 调用 | 20 | 40 |
| 工具调用 | 100（调度器每案固定查询 5 个） | 100（模型每案自主选择 5 个） |
| 输入 Token | 93,466 | 216,619 |
| 输出 Token | 1,344 | 5,760 |
| 模型累计延迟 | 115,866 ms | 385,275 ms |

Baseline 相比 Hybrid 使用约 2.32 倍输入 Token、4.29 倍输出 Token和 3.33 倍模型累计延迟。两种模式的工具缓存和数据库查询耗时未计入模型延迟。

## 分数据来源

| 数据来源 | Hybrid 全项通过 | Baseline 全项通过 |
|---|---:|---:|
| 人工编写 | 10/10 | 7/10 |
| 规则生成 | 9/10 | 4/10 |

Hybrid 唯一失败是 `refund_missing_evidence_001` 的 LLM 语义路由输出 `other`；该案例的最终裁决、责任方和复检分流仍全部正确，因为当前 Skill 路由使用可信的 `business_type=refund` 输入，而非 LLM 候选类型。

## Baseline 失败分析

| 案例 | 主要失败 | 根因分类 |
|---|---|---|
| `refund_conflict_004` | 退款成功但无入账流水，仍判定退款完成 | 跨源冲突漏判 |
| `refund_historical_policy_001` | 引用了正确的旧政策 v1，却把 50 小时误算成超过 72 小时 | 时间计算错误 |
| `refund_missing_001` | 无退款记录，却受客服话术影响判为“退款记录冲突” | 对话说法污染业务事实 |
| `refund_missing_002` | 裁决正确，但不必要地转人工且漏引支付证据 | 复检过度、证据引用不完整 |
| `refund_missing_004` | 未发起退款被判为到账超时 | 流程阶段混淆 |
| `refund_missing_evidence_001` | 裁决正确；首轮评测仍要求引用不存在的售后证据 | 评测器口径缺陷 |
| `refund_overdue_001` | 处理超过 5 日仍判定 SLA 内 | 时间阈值误判 |
| `refund_overdue_002` | 处理超过 5 日仍判定 SLA 内 | 忽略当前时间与退款发起时间差 |
| `refund_within_002` | 47 小时内的结论正确，但不必要地转人工且漏引订单/支付证据 | 复检过度、证据引用不完整 |

其中 `refund_missing_evidence_001` 暴露的是评测实现问题：首轮口径要求四类证据一律被引用，即使工具明确返回 `not_found`。代码已修正为“模型必须引用工具实际返回的全部证据”；原始 JSON 保持不变，未通过重跑覆盖首轮结果。

## 结论

当前数据支持三个具体判断：

1. 单 Agent 能稳定完成真实并行 Function Calling：20 个案例均在第一轮调用 5 类工具，第二轮输出严格 JSON，100 次工具调用无参数或协议错误。
2. 仅约束 Evidence ID 不能解决业务推理错误。Baseline 没有伪造证据，但仍会算错时间、混淆退款阶段或让客服说法覆盖系统事实。
3. Hybrid 的确定性政策时间检查和跨源融合显著降低错误，同时减少 Token 和延迟；代价是当前最终裁决主要由代码规则决定，LLM 的价值集中在对话语义提取。

因此下一阶段不增加更多 LLM Agent。应先把 LLM 输出用于可测量的用户主张、客服承诺和争议对象提取，并增加模糊表达、反事实客服承诺和多轮对话案例，再评估语义结果是否改善最终裁决。

原始逐案结果与调用轨迹见 `compare_gpt-5.4-mini_2026-08-22.json`。
